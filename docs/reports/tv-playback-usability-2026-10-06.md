# TV 播放页交互易用性测试

日期：2026-10-06。代码：`3432f10`，分支 `codex/tv-search-input-focus`。

## 范围与结论

本轮测试本地真实播放页，使用 Chrome 方向键、Enter 和 Escape 模拟遥控器可上报的按键，覆盖 `1280 × 720` 与 `1280 × 378`。检查焦点、实际媒体状态、全屏、菜单及播放返回，不修改播放逻辑。

核心控制链路可用，但发现三个需要优先处理的卡点：返回层级、设置子菜单不可达、换源后焦点丢失。不能据此判定电视遥控器交互已经顺畅。

不是 Q7F Pro 真机验收。本次开发日志中的 126 条事件均来自桌面浏览器；没有本轮电视端按键、固定坐标虚拟点击或只移动焦点的返回事件。现有自动化回归覆盖部分电视事件模型，不替代第三方电视浏览器实测。

## 本轮操作记录

1. 搜索“庆余年”，以 Enter 打开“庆余年 第一季”，实际进入 `dyttzy/35200` 播放第 1 集。
2. Enter 进入网页全屏，打开设置；上键进入进度条而非菜单，返回时出现异常跳转。
3. 直接重新打开播放 URL，隔离搜索卡片的播放准备状态；复测暂停、播放、进度、音量、下一集及自动隐藏。
4. 暂停状态下，上键进入进度条，右键从约 `130.62s` 前进到 `140.62s`，下键返回播放按钮；媒体保持暂停。
5. 确认恢复播放，左右移动到音量，Enter 静音并再次恢复；进入第 2 集后保持网页全屏和下一集按钮焦点。空闲后控制栏隐藏，方向键重新唤出。
6. 退出全屏，Enter 打开线路并切换到魔都资源 `mdzy/16636`；换源成功继续第 2 集，但焦点丢失。
7. 检查短视口：网页全屏控件可显示，非全屏播放器和线路区域需要明显的垂直滚动。

## 优先问题

### P1：返回没有遵循菜单 → 全屏 → 页面层级

- 从搜索进入播放，打开全屏设置，再按 Escape：URL 从 `/play` 返回 `/search`，全屏播放器 DOM 却仍覆盖搜索页，随后黑屏；需要重新导航恢复。
- 直接加载播放 URL 再打开全屏设置：Escape 后仍为全屏和设置展开状态，没有关闭菜单。
- 两次实际日志均记录了 Escape 和 `fullscreenWeb: true`；区别在于是否存在搜索卡片创建的播放准备意图。
- 原因：`src/components/playback-preparation/PlaybackPreparationProvider.tsx:498` 对 Escape 没有采用 `tvPreparing` 边界，首帧后的 `ready` 意图仍可触发 `cancel()` 与 `router.back()`；播放器适配未统一提供设置/网页全屏的返回层级。
- 建议：TV 准备阶段结束后不再由准备层接管返回；当前菜单优先关闭，其次退出网页全屏，最后才离开页面。兼容第三方浏览器的焦点型返回；同时检查离开路由时全屏 DOM 清理。

### P1：设置图标能确认，设置内容却无法用方向键选择

- 打开“播放速度”菜单后，焦点停在设置图标。上键进入进度条，下键回设置，右键进入画中画；没有进入菜单的方向路径。
- 本次 DOM 观察：`.art-setting-item` 是 `div`，`tabIndex = -1`，没有交互角色。焦点高亮只在控制栏上，不在播放速度选项上。
- 原因：`src/app/play/page.tsx:1118` 的上下导航固定选择进度条/上次按钮，菜单没有独立的焦点范围。
- 建议：继续适配 ArtPlayer 现有菜单，而不是增加第二套控制层。打开时进入菜单，方向键选择速度，确认应用，返回恢复设置图标。

### P1：换源成功后没有可见焦点

- Enter 选择魔都资源后，该项被置顶并成为禁用的“当前线路”，`document.activeElement` 变为 `body`。媒体重新播放后焦点仍没有恢复。
- 原因：`src/components/player/EpisodeSelectorSources.tsx:138` 在当前线路不可再切换时禁用按钮；`src/app/play/page.tsx:680` 只在页面加载依赖变化时安排一次初始焦点，没有换源后恢复。
- 建议：为当前线路保留可聚焦但不重复切换的语义，或在换源完成时显式恢复到稳定的线路/播放器入口，避免用户猜测下一次确认会操作哪里。

## 次要易用性风险

- P2：全屏控制栏没有选集、换源入口，需退出全屏再找到页面下方的选集与线路区域。保留已有原生控件方案，后续可考虑给同一控制栏加明确入口，不另造播放器控制层。
- P2：线路名称、状态、片名与测速仍混用约 10–14px 字号；`1280 × 378` 非全屏视口下播放器高度超过可视区域，操作区容易落在屏外。需真机观察远距离辨识与滚动步数，暂不视为已证实的电视操作阻断。
- 风险：播放页外围方向导航仍依赖电视浏览器，`src/components/ui/AppShell.tsx:28` 的浏览导航只启用首页、历史、搜索。当前桌面测试不能证明电视上的选集、线路网格不会发生焦点跳跃。

## 三个 P1 修复复测

同日，在 `3432f10` 基础上完成修复，随本轮 TV 适配提交。以上发现保留为修复前证据。

- 返回：准备层在 TV 首帧完成后不再接管 Escape；播放器依次返回设置子菜单、关闭设置、退出全屏、返回页面，支持 Escape、BrowserBack 和 Android keyCode 4。退出全屏恢复入口焦点，销毁前将 body 上的播放器移回宿主，防止残留黑屏。焦点型返回增加菜单/全屏边界处理；已有模态弹窗继续由其自身处理。
- 设置：复用 ArtPlayer 原生面板与点击行为，进入菜单自动聚焦，方向键移动，确认选择播放速度，原生面板切换后恢复焦点；沿用确认防重复与原有高亮，不新增控制层。
- 换源：TV 当前线路保持可聚焦、语义禁用且不能重复换源；列表重排丢失焦点时恢复原线路按钮。Web 当前线路仍使用原生 disabled。
- Chrome 实播复测：搜索进入全屏设置，方向键选中显示为 `1.3` 的选项，媒体实际速度为 `1.25x`（原生菜单已有的取整显示）；返回子菜单/设置/全屏均不离开 `/play`，最后返回 `/search` 无残留播放器。魔都与电影天堂双向切换后，当前线路保持原生可聚焦及 4px 高亮，媒体继续播放。
- 自动化补充：准备层完成后 Escape 不接管；真实 ArtPlayer 菜单方向/确认/重复虚拟点击、三种返回键、焦点型菜单返回、模态弹窗优先、退出全屏焦点、全屏卸载清理；TV/Web 当前线路和重排焦点回归。原有控制栏自动隐藏、方向唤醒、快进后离开进度条测试继续保留。
